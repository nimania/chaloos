# ربات تلگرام وضعیت جادهٔ چالوس 🛣️

سیستمی که می‌گوید جادهٔ چالوس همین الان **باز**، **بسته** یا **یک‌طرفه** است،
هر وقت وضعیت عوض شد در کانالت خبر می‌دهد، و **آخرین خبرهای محور** را هم می‌دهد.

**دستورها:** `/status` (وضعیت) · `/news` (خبرها) — یا بنویس «چالوس» / «خبر».

## منبع‌ها (به ترتیب اولویت)
1. 🥇 کانال **چالوس سیتی** → `t.me/s/chaluscity1` (بدون نیاز به توکن)
2. 🥈 کانال **جاده چالوس** → `t.me/s/jadeh_chalus` (بدون نیاز به توکن)
3. 📰 جست‌وجوی خبری (بازتاب سامانهٔ ۱۴۱ / پلیس راه)
4. 🗺 بلد

وضعیت راه به‌ترتیب از کانال‌های تلگرام و منابع پشتیبان دریافت می‌شود؛ برای گردآوری خبرها، هر دو کانال بررسی و مطالب تکراری پالایش می‌شوند.

از روی واژگان رسمی (بازگشایی / مسدود / انسداد / یک‌طرفه / دوطرفه) وضعیت را درمی‌آورد؛
برای خبرهای مبهم می‌تواند از Gemini (همان کلید پندار) کمک بگیرد.

> ⚠️ مرجع نهایی همیشه پلیس راه، تابلوهای مسیر و ۱۴۱ است.

> **چرا این شکلی؟** چون API رسمی و باز وجود ندارد. منبع معتبر، متن/خبر است و باید خوانده و دسته‌بندی شود.

## 🟢 راه پیشنهادی: GitHub Actions (دقیقاً مثل پندار، رایگان، بدون VPS)

این نسخه هر ۳۰ دقیقه خودکار روی گیت‌هاب اجرا می‌شود و **فقط موقع تغییر وضعیت** در کانالت پست می‌گذارد — همان الگوی `@pendario`. پراسس دائمی یا سرور لازم نیست.

### مرحله‌ها
۱) **ربات بساز:** در تلگرام → **@BotFather** → `/newbot` → توکن را بردار.

۲) **کانال مقصد:** کانالی که می‌خواهی هشدارها آنجا بروند را بساز (یا همان کانال موجود)، و این ربات را در آن **ادمین** کن.
   - آیدی کانال: اگر عمومی است `@username`، اگر خصوصی است آیدی عددی مثل `-1001234567890`
     (یک پست کانال را برای **@userinfobot** فوروارد کن تا آیدی را بدهد).

۳) **کد را در یک ریپو بگذار** (می‌توانی مثل پندار مستقیم روی سایت گیت‌هاب آپلود/ادیت کنی). همهٔ فایل‌ها از جمله پوشهٔ `.github/workflows/` باید باشند.

۴) **Secrets را اضافه کن:** در ریپو → Settings → Secrets and variables → Actions → New repository secret:
   - `TELEGRAM_BOT_TOKEN` → توکن مرحلهٔ ۱
   - `ALERT_CHAT_ID` → آیدی کانال مرحلهٔ ۲
   - `AI_API_KEY` → (اختیاری) همان کلید Gemini پندار

۵) **تست:** تب **Actions** → ورک‌فلو «چک وضعیت جاده چالوس» → **Run workflow**.
   اولین اجرا فقط وضعیت را ثبت می‌کند (هشدار نمی‌دهد). برای دیدن یک پست آزمایشی، یک‌بار متغیر `ALWAYS_POST=1` را موقتاً در workflow ست کن.

بعد از این، هر ۳۰ دقیقه خودکار چک می‌شود و وضعیت روی `state.json` در ریپو نگه داشته می‌شود (مثل برنچ state پندار). زمان‌بندی را از خط `cron` داخل `.github/workflows/chalous.yml` عوض کن.

**خبرها:** ورک‌فلو دوم (`chalous-news.yml`) روزی دو بار (۷ صبح و ۶ عصر) یک دایجست «آخرین خبرهای محور چالوس» در همان کانال پست می‌کند. اگر نمی‌خواهی، این فایل را پاک کن یا ساعت‌هایش را عوض کن.

## ⚙️ راه جایگزین: اجرای دائمی (برای پاسخ به دستور /status)

حالت GitHub Actions فقط **هشدار تغییر** می‌دهد. اگر می‌خواهی ربات به پیام کاربر هم جواب بدهد (`/status` یا «چالوس» → وضعیت لحظه‌ای)، به یک اجرای دائمی نیاز است (VPS/سرور):

```bash
cp .env.example .env     # توکن و ALERT_CHAT_ID را پر کن
pip install -r requirements.txt
python bot.py
```
تست سریع بدون تلگرام: `python chalous_status.py`

برای اجرای دائمی با systemd یا screen، پایین همین فایل نمونه هست.

## فایل‌ها
| فایل | کار |
|------|-----|
| `chalous_status.py` | هسته: خواندن منبع (کانال/خبر/بلد) + تشخیص وضعیت + خبرها |
| `check_once.py` | یک‌بار‌اجرا برای **GitHub Actions** — هشدار موقع تغییر وضعیت |
| `news_digest.py` | یک‌بار‌اجرا — دایجست خبری در کانال (صبح/عصر) |
| `bot.py` | ربات دائمی: پاسخ به `/status` و `/news` + هشدار (برای سرور) |
| `.github/workflows/chalous.yml` | چک وضعیت هر ۳۰ دقیقه |
| `.github/workflows/chalous-news.yml` | دایجست خبری، روزی دو بار (۷ صبح و ۶ عصر) |
| `.env.example` | نمونهٔ تنظیمات (برای حالت سرور) |
| `requirements.txt` | فقط `requests` |

<summary>نمونهٔ systemd برای حالت سرور</summary>

`/etc/systemd/system/chalous-bot.service`:
```ini
[Unit]
Description=Chalous Road Status Bot
After=network.target
[Service]
WorkingDirectory=/opt/chalous-bot
ExecStart=/usr/bin/python3 /opt/chalous-bot/bot.py
Restart=always
RestartSec=10
[Install]
WantedBy=multi-user.target
```
```bash
sudo systemctl enable --now chalous-bot
sudo journalctl -u chalous-bot -f
```
